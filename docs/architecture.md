# 砚稿商业版架构

## 两种客户端与同一服务

Windows x64 客户端通过 WebView2 加载运营方工作台。浏览器访问同一地址。两端各自持有 HttpOnly 会话 Cookie，通过同一账号读取手稿、题录、余额和流水。上游密钥、学科提示词、发码权限及 AI 请求的结算逻辑全部在服务端。EXE 内只包含原生窗口、WebView2 SDK 运行组件、组件许可证与默认服务地址。

~~~mermaid
flowchart LR
    W[浏览器] --> H[HTTPS / Caddy]
    E[Windows EXE / WebView2] --> H
    H --> A[FastAPI · 邮箱身份与会话]
    A --> D[账号工作区 · DOCX · 文献]
    A --> J[学术写作 Agent]
    A --> O[运营后台]
    O --> P[模型目录与加密密钥]
    O --> V[套餐与兑换码]
    J --> P
    J --> L[点数账本与任务记录]
    V --> L
    P --> M[本机或商业模型 API]
    A --> S[SMTP]
    D --> B[(SQLite WAL)]
    L --> B
~~~

当前部署单元为单主机、一个 API 进程和持久卷。Windows 本机可用启动脚本拉起两款 CPU 模型。Linux 容器通过配置的接口调用已有模型服务。Caddy 接受公网流量，内部服务端口仅在 Compose 网络可用。

## 业务责任

| 组件 | 关键行为 |
|---|---|
| accounts.py | 邮箱验证码注册、登录、重设密码、退出、账号停用后的会话失效。密码经独立随机盐 scrypt 派生。数据库仅存会话令牌摘要。 |
| store.py | 数据模型、事务与密钥。点数用整数表示。SQLite 写事务使用 BEGIN IMMEDIATE，余额有非负约束，账本有业务唯一键。 |
| control.py | 管理员可以配置兼容接口、替换或清除密钥、测试模型列表、修改价格及输出上限、上下架套餐、批量发码和停用未兑码。变更记入管理员审计表。 |
| commerce.py | 用户查询套餐、兑换和流水。发码快照记录发行时的点数及参考售价。完整码仅在发行时交付一次。兑换在同一事务中标记已兑并入账。 |
| agent.py | 根据稿件、选区、任务和作者要求选择专家，组织证据约束；计算报价、调用模型、复核引文和新增百分数、结算或退点。 |
| formatting.py / literature.py | DOCX 副本排版与多库题录检索。两条路径均经过会话校验。 |
| 桌面构建 | C# WinForms + Evergreen WebView2。源码构建时固定 SDK 包版本与 SHA-256。启动器解包到当前用户目录，工作台仅在指定服务源内导航，检索外链用系统浏览器打开。 |

## 兑换码与计费

运营方在后台设置套餐点数与参考零售价，生成一批高随机度兑换码，在自己的销售渠道交付。用户提交兑换码后立即入账。套餐以后改价不会影响已经发行的码。后台展示发码数量、已兑数量、已停用数量和兑换面额。参考价供运营定价使用，销售收入和收款凭证由实际销售渠道记录。

1. 客户端提交当前稿件、专家、深度和模型获取报价；服务端从数据库读取现行价格，计算本次最高预留点数。
2. 用户确认后发送唯一任务号与报价指纹。若价格或内容变化则重新报价。余额不足时直接返回，模型调用尚未开始。
3. 写事务原子创建任务并预留点数。期刊评审包含草案与复核两次调用。
4. 模型使用量可得时，实收为「调用数 × 基础点数 + 向上取整〔（输入 Token × 千输入价 + 输出 Token × 千输出价）/ 1000〕」。每次调用未报告 usage 时仅计该次基础费。实收以用户确认的预留点数为上限。结算、退差额与记录结果在同一事务完成。
5. 失败退回全部预留点数；进程中断留下的超时任务在服务启动、下一次报价执行或钱包读取时回收。重复提交同一任务号不会产生第二次扣费；成功结果加密保留 24 小时供重试取回，账本与每次成功任务的模型、专家、调用次数、输入输出 Token 及实收点数继续保留。

初始价格可改。已安装的轻量 0.5B 模型每次 1 点，标准 1.5B 每次 2 点，初始千 Token 加价均为零。期刊评审对应 2 点与 4 点。两个本地模型用于跑通产品体验；商业客户可选的更大模型由运营方在后台配置。

## 学术专家与约束

提示词采用本项目原创表达，取材于前期调研中有关证据台账、审稿反馈、局部修订和方法核查的设计。学术编辑、统计方法、工程计算、社会科学、人文史学、环境科学六种专家，分别关注论证关联、因果边界、基线复现、访谈与抽样、史料出处和空间尺度。自动匹配按题目、要求和选区中的学科线索路由，可由作者手动指定。

基础指导重解释；专业研究重方法与证据；期刊评审追加一次独立的模型复核。作者始终可以查看、采纳、忽略、撤销写作建议。只有题录时，提示词约束模型不可声称核读全文；程序核对新增引文编号与百分数，不能替代领域专家对事实的核查。

| 调研材料 | 应用中的对应实现 |
|---|---|
| [Nature Skills 工作流介绍](https://x.com/jynong26/status/2062908321582203020) | 将大纲、润色、评阅分为不同任务。传给模型的题录带有真实编号和 DOI，输出中的新增引文编号逐项与题录比对。 |
| [证据台账与作者判断](https://x.com/kelmand1/status/2119626180391579931) | 提示词要求标注缺证据的段落；界面先展示建议，由作者采纳。未经材料支持的新百分数单独提示。 |
| [开题研究与方法约束](https://x.com/intimacylabx/status/2123331956821852409) | 统计专家检查抽样、混杂与相关性表述，社会科学专家区分采访材料与推断，环境专家保留观测窗口和空间尺度。 |
| [Quillwork 的局部修改思路](https://x.com/tiagerbao/status/2115423027479580797) | 润色选区保留前后文，采纳前检查原稿版本，保留撤销入口。 |

## 手稿、备份与上线

账号工作区按用户主键隔离，更新携带版本号。两个客户端同时编辑时，后提交的一端保留本机待同步内容，可选择将冲突手稿合并为独立副本。旧版浏览器草稿经当前使用者确认后才导入账号。Word 文件在内存中处理，格式副本按需下载。文稿正文以账号工作区数据保存，运营部署应限制数据库卷和备份的访问权限。

定期备份数据库与主密钥；对在线 SQLite 使用 backup API 或停服后复制完整数据目录，避免只复制正在写入的数据库文件。恢复必须使用原主密钥，才能解密模型凭据和暂存结果。采用自管主密钥时设置 YANFOLIO_MASTER_KEY 为 Fernet 格式；未指定时在持久卷生成。多台 API 同时写入时需迁移数据库和共享限流／任务协调机制。本版按单实例验收。

生产入口设为 HTTPS，配置独立 SMTP，持久化服务卷。管理员通过服务端命令创建。登录页仅在回环环境且未配 SMTP 时使用本机测试信箱。EXE 使用 Windows x64 和 WebView2 Evergreen Runtime，本次构建未做 Authenticode 发行签名。微软的运行时分发方式及支持环境见[官方分发说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)。
