# 文档服务的部署与恢复

砚稿 2.1 将公开产品页、邮箱账号、在线写作、文档原件和点数账本放在同一个服务域名下。浏览器从官网进入，桌面客户端启动后进入受保护的个人中心。客户机只需要 Windows x64、WebView2 运行时和可达的运营方服务地址。

## 页面与持久数据

| 入口 | 服务内容 |
|---|---|
| / | 公开宣传页，原创纸质等高线摄影主视觉，可切换的学术润色、文献核对和 Word 排版示例。视觉参考[原帖](https://x.com/i_am_oil_oil/status/2123969800787640684)及 [Oil Art Landing 公开案例](https://ui.oiloil.org/art-landing/)。 |
| /profile.html | 已验证邮箱、资料、注册时间、可用点数、文档用量、设备会话与远程退出。 |
| /drive.html | 账号文档、项目文件夹、上传任务、版本、下载与回收站。网页与桌面请求同一资源。 |
| /studio | 写作工作台。可把编辑稿导出至云文档，也可从文档库选取 DOCX 导入写作或按原件排版。 |
| /admin.html | 运营后台的“文档资源”展示服务器磁盘容量、实际存储量、传输预留和各账号配额。暂停上传时下载继续可用。 |

SQLite WAL 保存身份、所有权、目录、版本、预留、点数与审计。完整文件写入运营方的私有持久卷，按不可预测的版本 ID 分片目录存放；所有下载请求通过同源服务鉴权。前端未提供公共分享链接。管理员的资源列表只展示容量和账号信息。

新账号与升级前的账号默认获得 **5,000,000,000 字节**，显示为 5 GB。当前文档、保留的历史版本和回收站共同计入已用空间；未完成上传单独预留。编辑器自动保存的工作区仍有独立的 8 MB JSON 上限，保存 DOCX 原件或副本后，文件计入个人云文档配额。配额独立于写作点数。

## 传输与回收

- 客户端在上传前申请整个文件的空间。串行写事务核查账号容量及存储卷可用量，并为其他活跃上传保留其尚待写入的空间。单文件最多 5 GB。按需分配磁盘，运营方需按用户实际使用量扩容。
- 每个 4 MiB 分片都校验 SHA-256。落盘并刷新后再提交分片偏移。崩溃产生的未提交尾部在下次写入时截断。重复提交相同分片返回已知进度。完成全部分片后才发布可下载的文件版本。
- 中断后在任一已登录客户端重新选择原文件。客户端复核此前各分片内容后继续；上传任务在最后一次成功写入后保留 24 小时。
- 下载支持字节范围请求。上传新版本时核查所基于的版本 ID，防止两个设备覆盖对方工作。还原旧版切换当前版本，旧文件字节保留至用户删除该版。
- 移入回收站保留 30 天。永久删除或过期后，事务释放账面配额，磁盘删除失败会排队重试。维护任务在启动及运行中每 10 分钟执行。
- 文档库同步的是服务端保存的文件和版本。选中的本地文件需要主动上传；本版没有接管 Windows 资源管理器里的用户目录。

## 部署

按 README 配置正式域名、HTTPS、SMTP 和模型端点，再在服务器运行 deploy/compose.yaml。Compose 为账号数据和文档对象分别挂载 service 与 documents 两个具名卷，Caddy 继续使用独立证书卷。默认监听只对外开放反向代理。4 MiB 的传输分片在现有 40 MB 请求体限制内。

本机开发时对象目录默认位于 YANFOLIO_DATA/objects。生产通过 YANFOLIO_OBJECT_DIR 指定由服务进程独占的持久化目录，可使用主机块存储或挂载卷。部署拓扑基于单个写入实例和单一文件卷；跨区域复制、S3 服务和 Windows 文件系统级同步需要另外部署或开发。

原有账号库在启动时新增云文档表，原有手稿、点数流水及账号身份继续使用。升级既有服务前应备份数据库、主密钥和已有文档卷。以后新增账号、调整支持的模型和配额、暂停上传等运营动作在服务端生效。Windows 版本发布时用 scripts/build_desktop.py --service-url 指定正式地址，再用 scripts/build_web.py 更新运营部署包。

## 备份与恢复

运行备份的账号需能读取数据库及文档卷，并有足够临时磁盘空间。备份过程中在同一写事务保护下取得 SQLite 快照，为不可变的文档对象建立临时硬链接；文件系统不支持硬链接时在锁内复制对象。随后在写锁之外读取、校验并归档文档。会话、验证码和未完成传输不进入恢复后的服务。已完成的账号、资料、文档版本、回收站、配置和点数记录保留。备份包是私有数据，应存放在限制访问的备份介质。

~~~sh
python scripts/cloud_backup.py backup /backup/yanfolio-2026-11-21.zip
python scripts/cloud_backup.py restore /backup/yanfolio-2026-11-21.zip /restore/yanfolio --key-file /private/yanfolio-master.key
~~~

备份命令输出到一个新的文件。主密钥单独保管，不包含在备份包内。还原时核对密钥指纹、数据库完整性、外键和每个版本的分片摘要，再发布新的数据目录。已有目标目录会被拒绝。容器中执行命令时，需要挂载备份介质；还原生成的 objects 子目录应作为对应文档卷的数据使用。切换流量前可用测试域名检查账号登录、配额和真实文件下载。
